## 1. Project Description

OCR Assistant 用于从虚拟机外获取可见的文件内容。用户能够在虚拟机中查看文件，但无法直接复制文件出来；系统通过 CLI 接收虚拟机画面的截图或拍照图片，在外部机器上本地识别、整理和轻量校订，快速输出 Markdown 初稿。

材料主要是英文文档，包含表格和少量代码，几乎没有手写内容。输入可能有几十页，也可能有模糊、小字、倾斜、屏幕摩尔纹及复杂表格。用户明确选择第一轮速度优先，接受一定识别误差；通过保留原图、识别初稿和修改记录，为后续深入语法语义检查及必要的人工核对提供依据。MVP 的成功产出是可追溯初稿，不代表内容已完整校验。

### 1.1 Confirmed MVP Scope

| 项目 | MVP 需求 |
| --- | --- |
| 入口 | CLI，支持批处理；处理核心可以独立于交互界面运行 |
| 输入 | 通过文件、目录或有序列表手动批量导入截图和照片，归入同一文档任务 |
| 内容 | 英文正文优先，兼顾标题、目录、列表、表格和少量代码 |
| 识别 | 本地快速 OCR 或文档多模态模型，恢复基本阅读顺序与结构 |
| 校订 | MVP 保留文字校订模型，只做快速词级纠错和明显空格、断词修复 |
| 反馈 | 记录失败页、已发现的问题和修改差异，结束时集中反馈，不逐项等待人工确认 |
| 输出 | Markdown 初稿；同时保留原图对应关系、识别初稿和必要的配套资源 |
| 批量 | 按页、按区域处理几十页材料，显示进度并保存中间结果 |
| 技术基线 | Python 3.12；后续通过 uv 初始化及管理依赖 |

后续范围包括句子级语法和语义二次校验、必要的人工复核支持、自动截图、自动翻页和 Markdown 转 PDF。完整网页或桌面界面不作为 MVP 依赖；按需打开的核对报告可在后续复核功能中评估。手写专门优化、云端模型调用、训练或微调当前没有纳入 MVP。具体 CLI 参数、输入图片格式集合及运行数据约定在实施准备时确定。

## 2. Architecture Design

### 2.1 Data Flow

~~~mermaid
flowchart TD
    A[CLI 导入并指定图片顺序] --> B[保存原图与页面记录]
    B --> C[可选的低成本图像校正]
    C --> D[快速 OCR 与基本版面解析]
    D --> E[轻量词级校订]
    E --> F[Markdown 初稿与批次反馈]
    F -.后续独立运行.-> G[深入语法与语义校验]
    G --> H[按需对照原图和人工调整]
~~~

所有处理位于虚拟机外。MVP 使用本地文件输入和本地模型推理；准备阶段可以下载依赖与模型，处理文档不依赖云端识别服务。CLI 负责启动任务、传递参数和报告状态，核心处理不依赖浏览器。自动截图将来作为新增输入方式接入同一处理链路；二次校验可以读取已保存初稿独立运行，不要求重新 OCR 整份文档。

### 2.2 Model Candidates

| 路线 | 候选 | 设计职责与取舍 |
| --- | --- | --- |
| 优先验证的双模型路线 | PaddleOCR-VL 系列（调研候选为 1.6）+ Qwen3-4B-Instruct-2507 | 文档模型负责快速转写和基本结构；文字模型仅做轻量词级纠错，分别测量两步耗时和收益 |
| 单模型对比路线 | Qwen3-VL-4B-Instruct；有必要时比较 8B | 同一多模态模型承担转写与轻量校订；比较产出初稿的总耗时、资源和误修改，不在首轮执行深入语义审查 |
| 条件性备选 | PaddleOCR / PP-StructureV3 | 当文字坐标、表格单元格坐标或 CPU 路径存在具体需要时再评估，暂不扩大首轮模型比较范围 |

Python 3.12、uv 和 CLI 入口已确认。模型权重版本、精度或量化方式、推理框架、CLI 命令契约及数据持久化实现尚未确定。候选名称是验证起点，不代表安装完成、兼容性已验证或效果已获认可。PaddleOCR-VL 本身是包含文档视觉模型的解析方案，不等同于通用聊天模型；其流水线内部还可能包含版面分析等辅助模型。

第一轮选型以产出初稿的速度和批处理成本为优先，同时记录字符错误、漏行、结构恢复和误修改，衡量速度与准确性的取舍。小模型或“简单检查”提示词并不自动等于快速，需实际测量校订增量耗时。若现有候选不能满足速度目标，再评估更轻的识别或校订配置。不同路线在验证阶段做离线对比，MVP 不要求每页执行多模型交叉检查。单模型重复检查或两个模型结果一致均不构成内容正确性证明。

### 2.3 Batch Processing

- 文档总页数不等于单次模型上下文大小；按页、按区域推理，限制单次图片尺寸、上下文和并发。
- 保存每页识别初稿、校订结果、状态和错误，支持中断后继续及单页重试。
- 跨页内容先依据页序与基本版面结果合并；第一轮只携带词级纠错所需的有限上下文，深入跨页语义分析留到二次校验。
- 通过页面顺序与覆盖信息检查遗漏；照片存在重叠时，只有证据充分才去重，不按相似语句直接删除。
- 跨页表格须确认表头与列对应；无法可靠合并时保留分段结构和原图，显示待核对标记。
- 产品不预设很小的总页数限制；可处理规模仍受磁盘、内存和时间约束，实际范围通过批量测试确定。
- 单页技术失败可有限重试并记录，允许其他页面继续；已发现的内容疑点集中反馈，不在首轮为每个疑点反复看图或等待人工输入。
- 模型持续不可用或资源故障导致任务无法继续时，保存进度并给出一次明确的终止或暂停信息。区分初稿已生成、存在失败页和后续已校验等状态。

## 4. Module Design

以下为职责划分，不固定类名、函数签名或实现框架。

### 4.1 Import and Page Management

通过 CLI 指定图片文件、目录或有序列表，将其归为一个文档任务。页面顺序必须明确、可查看和覆盖，避免仅凭不可控的文件枚举顺序处理。保存原图与稳定的页面标识，使重试、校订和导出始终可以关联来源；输入文件不被校正结果覆盖。MVP 不要求内置图片预览或拖拽界面，必要时可通过已有图片查看器检查原图。

### 4.2 Image Preparation and Quality

第一轮根据实际需要采用低成本裁剪、旋转或图像校正，并测量其耗时与收益；处理结果作为原图的派生版本保存。不默认对每页执行昂贵的增强、多种预处理组合或反复局部识别。复杂透视、摩尔纹和模糊区域可留到后续按需复核；简单放大或生成式增强产生的细节不作为原文证据。

### 4.3 Document Recognition

识别正文、标题、目录、表格和代码区域，形成带页面来源和阅读顺序的识别初稿。尽可能保留区域坐标；具体粒度取决于所选模型。模型未提供可靠坐标时保留对应页面或裁剪图，不能虚构精确定位。

识别初稿与校订结果分开保存。第一轮记录已有的后端分数和明显技术异常，避免为了给每个词评估置信度增加模型调用。分数或模型自行声称的置信度不能直接当作准确率；识别成功也不代表没有内容错误。深入疑点检测、视觉复核和抽检支持属于后续校验能力。

### 4.4 Text Correction

MVP 保留文字校订模型，第一轮只做快速词级纠错，无须逐条人工确认。输出修改前后内容及对应位置；尽量返回必要的修改项并由程序应用，减少重新生成整篇文章的开销，实际收益通过基线验证。

| 内容类别 | 默认规则 |
| --- | --- |
| 普通英文单词 | 自动处理明显字符混淆和常见拼写错误，例如 dup1icate 到 duplicate、becuase 到 because |
| 排版 | 根据版面结果整理段落、标题、列表和阅读顺序；英文行末连字符需区分断词与原有连字符 |
| 技术名称和专业术语 | 识别驼峰名称、模型名、类名及专有词；即使出现在目录或正文中，也不按常用词典盲目替换 |
| 数字、日期、编号和 ISBN | 保留字符、前导零及小数点；格式检查可提示异常，不凭规则或常识改成另一组数据 |
| 代码 | 保留标识符、字符串、符号和可辨认的缩进；第一轮不进行程序语义修改或深入语法分析 |
| 句子级语法 | 第一轮保留 It was make by me.；make 本身是合法单词，make 到 made 的被动语态纠正属于二次校验 |
| 语义和上下文 | 时态、语态、指代、逻辑关系和上下文一致性检查留到后续，第一轮不为了合理或通顺改写句子 |
| 模糊或缺失内容 | 保留识别初稿及已有问题记录；不反复调用模型或阻塞整批任务，也不补写图中看不到的内容 |

双模型路线下，文字模型输入识别初稿、区域类别和少量必要上下文；单模型路线同样限定第一轮检查范围。后续二次校验可以复用文字模型并提供更完整的上下文，是否需要更强模型或视觉复核由效果决定。二次校验独立读取已保存结果，按需定位原图或请人工调整；若图片原文本身有语言错误，应把语言修改与 OCR 恢复分别记录。各阶段均保留原版本，不覆盖原始识别事实。

### 4.5 Feedback and Export

MVP 通过 CLI 提供处理进度和结束汇总，输出初稿、轻量校订差异、失败页及已经发现的问题。第一轮不要求用户查看每页，不以识别出所有内容错误为完成条件，也不把初稿状态标成内容已校验。

后续二次校验再集中呈现语法语义疑点，支持按需原图对照、局部重新识别和人工调整。核对报告可以是按需打开的本地文件，不要求运行 Web 服务；是否增加交互编辑界面由后续使用需求决定。

导出规则：

- 标题、段落、列表及代码块使用 Markdown；代码块语言无法确定时可不指定语言。
- 普通表格使用 Markdown 表格；合并单元格、多层表头等复杂结构可保留识别器产出的内嵌 HTML，并附对应图片。第一轮不为完善复杂表格阻塞整个批次；目标查看器和未来 PDF 导出需要验证兼容性。
- 表格结构无法确定时保留原图和明确的疑点说明，不静默丢弃表格或宣称结构已正确恢复。
- 图片中可见的链接文字可以转写，实际目标 URL 未显示时不补造链接。
- 保留页面到输出的对应关系；识别初稿、校订记录和相关图片随文档任务保存，Markdown 导出所需图片作为配套资源。

### 4.6 Evaluation

建立与源图对应、经人工核对的参考转写，区分已确定内容与不可辨认内容。分别比较识别初稿和校订版本，统计字符错误与漏行，并检查表格行列、数字、代码符号和章节页码。

单独记录词级校订修复的错误和引入的新错误；句子级错误在第一轮保留是范围约定，不能据此错误地判定词级校订不合格。分别测量 OCR、轻量校订及总耗时，记录峰值内存与显存、输入尺寸、模型版本及推理配置。对同一套样本使用一致的参考答案和处理条件。

MVP 以快速产出可追溯初稿为目标，允许一定内容错误；具体速度和误差取舍在基线后确定，不预先编造阈值。首轮检查页序、覆盖、技术失败记录和修改可追溯性，不以发现所有模糊词或消除所有语法语义错误为验收条件。后续二次校验再评估句子级纠错、语义疑点覆盖、原图核对及人工介入量；即使语法通顺也不代表逐字符合原图。
