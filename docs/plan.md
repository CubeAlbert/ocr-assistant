## 1. Milestones

### Milestone 1 — 方案与上下文初始化（已完成）

- **Expected Output:** 完整的 design、plan、task、current、decision 五份文档。
- **Acceptance Criteria:** 用户确认的 CLI 入口、输入、内容、速度优先、词级校订与后续深入校验边界、输出、Python 3.12 和后续 uv 选择均已记录；四张样图以目视评估身份归档；模型实测及实现任务保持待开始。
- **Dependencies:** 本次对话和 sample-pic/ 中的四张样图。

### Milestone 2 — 本地模型可行性验证（待开始）

- **Expected Output:** Python 3.12 验证环境、人工核对的样本参考答案、候选路线对比及初步选型结论。
- **Acceptance Criteria:**
  - 在后续实施开始时核对设备和系统，通过 uv 初始化项目并验证所选依赖与 Python 3.12 兼容。
  - 优先比较 PaddleOCR-VL + 小型文字模型与 Qwen3-VL 单模型路线；记录模型、配置和输入条件。
  - 比较识别初稿和词级校订版本的字符错误、漏行、误修改及基本结构恢复，不在首轮执行深入语法语义审查。
  - 分别测量 OCR、轻量校订和端到端耗时、内存及显存；按速度优先目标评估两台机器的可用性。
  - 验证词级与句子级边界：dup1icate 等常见错误可修正，It was make by me. 的语态问题留到后续二次校验。
  - 首先依据四张样图得出有范围限制的结论；对复杂表格和多页内容保留样本缺口。
- **Dependencies:** 后续开始实施的指令；设备信息、模型与依赖获取条件、样图参考答案。当前没有预设准确率或速度承诺。

### Milestone 3 — CLI 手动导入 MVP（待开始）

- **Expected Output:** CLI 多图导入、排序、快速 OCR、轻量词级校订和 Markdown 初稿导出的可运行流程。
- **Acceptance Criteria:**
  - CLI 接收图片来源和明确的页面顺序，保存原图对应关系，处理核心独立于交互界面。
  - 保存识别初稿、轻量校订结果和修改差异，记录失败页并集中反馈，不逐页要求人工确认。
  - 按正文、技术名称、表格数据和代码执行最小范围校订；完整句子语法、语义检查和交互复核留到后续。
  - 普通内容和表格可导出 Markdown；复杂表格按设计提供 HTML 或明确的图片与疑点表示。
  - 按页保存任务进度，处理失败可以单页重试或继续，重试不重复合并结果。
- **Dependencies:** Milestone 2 的模型与推理后端结论；实施时确定 CLI 命令契约和运行数据方案。网页与桌面界面不作为 MVP 依赖。

### Milestone 4 — 多页与困难样本验收（待开始）

- **Expected Output:** 用户目标机器上的 MVP 验收记录，包含适用范围、失败情况及剩余问题。
- **Acceptance Criteria:**
  - 用连续几十页文档验证顺序、跨页段落、进度保存和恢复，检查漏页、漏行及重复内容。
  - 增加合并单元格、多层表头、单元格换行及跨页表格样本，验证结构与数字准确性。
  - 对摩尔纹、小字和模糊内容记录残余错误、已有问题信号和来源，不要求第一轮发现全部内容错误或进行反复视觉复核。
  - 比较词级校订收益、新增错误及端到端速度，按 Milestone 2 后确定的速度与误差取舍评估。
  - 分开记录自动化验证与用户实际使用体验；确认 Markdown、HTML 表格和配套图片在目标查看器中可用。
- **Dependencies:** Milestone 3；补充样本及参考答案；目标机器上的实际操作。

### Milestone 5 — 后续扩展（非 MVP，待开始）

- **Expected Output:** 深入语法语义二次校验及按需人工复核、自动截图与翻页输入、Markdown 转 PDF 三类后续能力。
- **Acceptance Criteria:**
  - 二次校验可独立处理已保存初稿，检查句子语法及上下文语义，例如 It was make by me. 的 make 到 made；集中呈现疑点并按需对照原图、局部重新识别或人工调整。
  - 二次校验保存修改记录，不以语法通顺替代原图真实性；可以先复用文字模型，是否更换模型或增加可视化报告根据效果决定。
  - 自动采集检查遗漏和重复并沿用现有处理链路；PDF 输出验证分页、表格、代码及图片布局。
- **Dependencies:** MVP 完成并获得相应后续任务指令；三类扩展的执行先后按届时需求确定。

## 2. Key Dependencies

### External

- 两台机器均为 32GB 内存；用户报告第二台为 3080、16GB 显存。精确硬件、系统和驱动版本待核对。
- 本地模型和依赖需在实施阶段准备；Python 3.12 兼容性尚未安装验证。
- 已有四张样图；人工参考答案、真正复杂表格和连续多页样本尚待补充。
- 常规处理采用本地推理，没有已选定的云端服务依赖。

### Cross-cutting

- 顺序：先做速度与词级纠错基线，再构建 CLI MVP，随后验证多页批量适用范围；深入语法语义能力属于后续扩展。
- 来源追溯贯穿导入、图像校正、识别、校订和导出；保留原图与识别初稿。
- 总页数与单次推理资源分离；通过逐页处理、进度保存及有限并发控制资源。
- 复杂表格使用内嵌 HTML 的设计需验证实际查看器支持，也会影响未来 PDF 渲染。
- 不依据模型自报置信度、语句通顺或两次结果一致，单独判定内容正确。
- MVP 的初稿生成与后续内容校验分开记录；第一轮允许识别误差，保留来源和失败信息，不以逐项人工复核作为完成前提。
- 当前没有 Git 仓库；Git 是否初始化及提交安排在后续项目初始化时处理，本次不执行。
